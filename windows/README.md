# Dynamic Photo Wall — Windows

Windows 11の選択したディスプレイを、写真がゆっくり動くギャラリーにするWPF常駐アプリです。Windowsの壁紙設定を変更せず、Explorerの背面描画階層に接続します。写真はローカルで処理し、アップロードもテレメトリも行いません。

## 起動

**`release/windows/win-x64/DynamicPhotoWall.exe`をダブルクリック**すると起動します。Windows x64向けのReleaseビルドで、.NETランタイム・画像処理ライブラリ・アイコンを同梱した単一EXEです。DLLやPowerShellの操作、.NETの別途インストールは不要です。

同じディレクトリの`Dynamic Photo Wall`ショートカットも同じEXEを起動します。ビルド時に自動で作成・更新します。手動で再作成する場合は `windows\scripts\Create-Shortcut.ps1` を実行してください。

リポジトリ直下から `windows\Start-PhotoWall.ps1` を実行しても起動できます。EXEと同じディレクトリの `photos` を初期の写真フォルダーとして検出します。ルートの既存 `photos` を使う場合は「写真」設定から選択してください。保存済みの写真設定は維持します。

EXEとドキュメント・ライセンス類は `release/windows/win-x64/` に保存します。EXEを別のフォルダーへ移しても起動できます。写真はEXEに含めず、「写真」設定で選択します。設定・キャッシュは引き続きユーザーのLocalAppDataへ保存します。初回起動時には、同梱したネイティブライブラリを.NETがユーザーの一時領域へ展開します。

1. **使用ディスプレイ**で表示対象を1台以上選びます。つなげたい画面がある場合は、**画面グルーピング**で同じグループを選びます。
2. **写真**に写真フォルダーを追加します。複数フォルダーと再帰検索に対応しています。
3. **保存して表示開始**を押します。設定画面は閉じても構いません。
4. タスクトレイから開始・一時停止・次の構成・停止・設定・終了を操作できます。

**使用ディスプレイ → タスクバーを隠す画面**で、タスクバーの表示を画面ごとに指定できます。たとえば連結する2画面の片方だけを隠す設定も可能です。停止・終了、スリープ、対象画面が最大化アプリで覆われたときには、その画面のタスクバーを戻します。対象外の画面のタスクバーは変更しません。アプリが異常終了した場合も独立した復元用プロセスがタスクバーを戻します。「一般」では起動時の動作と再生操作を扱います。

## 複数ディスプレイ

**使用ディスプレイ**で表示対象を選び、**画面グルーピング**でつなぎたい画面に同じグループを選びます。**「独立して表示」の画面は、それぞれ単独で再生**します。たとえば画面1・2を「グループ1」、画面3を「独立して表示」にすると、1・2をまたぐキャンバスと画面3の単独再生を同時に使えます。「＋ グループを追加」で複数のグループも作れます。

写真・動き・ガラス風背景はグループ内で共通です。グループごとに構成と時計を持ち、ほかのグループへ写真が流れ込むことはありません。写真フォルダーや表示モードの設定は全グループで共通、開始・一時停止・次の構成・停止の操作は全グループへ適用します。

- 初期配置はWindowsの物理ピクセル座標です。カードはグループごとに色分けし、同じグループ内の端・中央へドラッグでスナップします。「配置を数値で調整」のX・Yで上下のずれやベゼルに相当する隙間を指定できます。変更は「保存して適用」または「保存して表示開始」で反映します。
- 「配置を数値で調整」内の「Windowsの配置に戻す」でOSの配置に合わせられます。OSの配置自体は変更しません。画面を新たに接続したときは「ディスプレイを再検出」で一覧を更新して選択してください。
- グルーピング画面の「テストパターン → 表示」を押すと、保存せずに現在編集中の画面選択・配置で位置と倍率を確認できます。写真フォルダーは不要です。ボタンが「表示停止」に変わり、もう一度押すと停止します。もともと写真を再生していた場合は、保存済み設定の写真再生へ戻り、一時停止状態も保持します。テストパターンの表示状態は保存しません。
- グループ一覧には作成済みのグループ数・画面数・所属画面を表示します。未割り当てのグループも「0画面」として表示し、設定を保存すると次回も一覧に残ります。
- 画面を外しても、そのグループの保存済み領域を空けたまま再生を続けます。再接続・解像度変更では該当グループの構成を作り直します。そのグループの全画面が外れた場合は再接続を待ち、ほかのグループは継続します。
- グループ内の全画面を同じ前景ウィンドウが覆う場合は、そのグループの時計を一時停止します。ほかのグループは再生を続けます。タスクバーは画面ごとに復元します。
- 以前の複数画面設定は「グループ1」として連結を維持し、以前のタスクバー設定も引き継ぎます。画面ごとの指定を保存すると個別の設定になります。

キャンバスの幅・高さの上限は32768px。物理サイズが異なる画面の実寸補正、画面の回転設定、Macなど別PCとの同期は今後の対応です。OSの表示倍率によらず各画面の物理ピクセルに合わせて切り出しますが、混在DPIの実機確認は残っています。

初回は自動で表示を始めません。保存後は、起動時の再生とWindowsログオン時の自動起動を設定できます。自動起動は現在ユーザーのRunレジストリに実行ファイルを登録します。移動後は設定し直してください。

## 見せ方

- **Gallery**: 画面の縦横比に合わせて最大5枚。写真全体を表示し、写真ごとに独立して更新します。更新時には位置とサイズも滑らかに変わります。
- **Scrolling Gallery**: 従来のGalleryとは別モードです。上下の余白は初期値で各8pxに抑え、写真がゆっくり横に流れ、画面外へ出た写真を新しい写真へ交換します。後続写真を先読みし、同時表示の重複を避けます。速度は「動き」から変更できます。
- **Vertical Pan**: 横幅を画面に合わせ、顔が上側なら写真の下側から上へ、顔が下側なら上側から下へ見せます。顔が見つからない場合は従来どおり下側から上へ進みます。
- 縦パンの幅は初期値で画面の96%を上限とし、中央に配置します。Windows標準のローカル顔検出で顔を見つけた場合は、顔全体と頭上の余白が見える幅・終了位置へ調整し、終了位置で3秒保持します。顔が見つからない写真は通常のパンを使用します。「表示モード」から表示幅と顔位置での停止を変更できます。
- **Horizontal Pan**: 画面より横長の写真を高さに合わせ、顔が左側なら右側から左へ、顔が右側なら左側から右へ見せます。顔が見つからない場合は方向をランダムに選びます。はみ出しがない写真は自動選択しません。
- **Zoom**: 横写真を画面いっぱいに表示し、中心を変えながら1.0〜1.08倍の緩やかな拡大・縮小を行います。
- 全画面のZoomでも顔を検出し、顔が画面内に入る縦位置とズーム中心を選びます。「表示モード」の「全画面表示でも顔が見える位置を優先」で切り替えられます。

顔を基準にした方向選択は「動き → 顔の反対側からパンを開始する」で切り替えます（初期値は有効）。複数の顔がある場合は、最も大きな顔の中心を基準にします。縦パンで顔位置に停止する設定も有効なら、同じ顔が見える位置で停止します。方向選択を無効にすると、縦は下から上、横はランダムという従来の動作に戻ります。横スクロールGalleryの方向は変更しません。

パンは物理ピクセルの距離÷速度で時間を決めます。初期値120px/秒、クロスフェード1.2秒、Gallery更新30〜60秒です。拡大率の初期上限は4倍です。**画面のネイティブ解像度より小さい写真も表示できます。** 粗さが気になる場合は「表示モード」の許容拡大率を下げてください。

抽選ウェイトはGallery 45 / Pan合計35 / Zoom 20です。適性のないモードとウェイト0のモードは候補から外れます。同じモードが3回連続しないようにするため、長期の実測割合は設定ウェイトから多少変わります。少数の写真では直近履歴の制約を緩めますが、1つのGalleryで同じファイルを重複表示しません。

GalleryとScrolling Galleryを両方有効にすると、Galleryのウェイト45を2モードで分けます。「表示モード」で個別に有効・無効を選べます。

背景は表示中の写真・切り取り位置に追従するガラス風の色合いです。パン、横スクロール、Galleryの個別更新に合わせて変化します。「見た目」の「表示中の写真に追従するガラス風の背景」で単色背景へ切り替えられます。写真の4pxのフチぼかしは削除しました。写真の表示サイズをフチ処理のために縮めません。

JPEG / PNG / WebP対応。EXIFの8方向の回転・反転を適用します。HEIC / HEIFにはWindowsの対応WICコーデックが必要です。コピー済みの同内容ファイルは別写真として扱います。

## 設定とログ

通常は `%LOCALAPPDATA%\DynamicPhotoWall` に保存します。

- `settings.json`: 設定。テンポラリファイルから置換して保存します。
- `metadata.json`: パス・サイズ・更新日時をキーにした画像情報キャッシュ。
- `faces.json`: ローカル顔検出で取得した顔位置のキャッシュ。
- `app.log`: エラーと復旧記録。約2MBで1世代ローテーションします。パスなどローカル情報を含みます。

設定が壊れている場合はコピーを保存して初期値で起動します。`--data-dir <directory>` で保存場所を変更できます。`--tray` は設定画面を開かず起動します（表示対象が未設定の初回を除く）。フォルダー変更は監視し、通知漏れに備えて5分ごとにキャッシュを使って照合します。

画像デコードはUIスレッド外で行い、画面に合わせたサイズを選びます。LRUキャッシュ予算は初期値256MiBで、全グループで共有します。この予算はキャッシュだけの値で、表示中・プリロード中・WPF/GPUのメモリは別に使用します。デコードは1件ずつ実行し、グループごとに次の構成を1つだけプリロードします。Scrolling Galleryでは次に流入する写真も先読みします。30fps制限は撤廃し、WPFの描画スレッドとDWMの画面合成にペーシングを任せています。パンはRenderTransformで動かすため毎フレームのレイアウト計算が不要です。アプリからDXGIのPresentを直接制御する方式ではなく、厳密な提示フレーム数はWPF・DWM・GPUドライバーに依存します。

## ビルドとテスト

Windows 11 x64、.NET 10 SDKが必要です。ソリューションは `windows/DynamicPhotoWall.sln` です。初回の復元にはNuGet接続が必要です。プロジェクト内の `.tools\dotnet` があればビルドスクリプトが優先します。

リポジトリ直下から実行します。配布物は `release/windows/win-x64/`、検証結果は `artifacts/windows/smoke-data/` に出力します。ルートへEXE・ショートカットをコピーしません。[生成物の共通規則](../docs/GENERATED-FILES.md)に従ってください。再ビルドする前に、起動中のアプリをタスクトレイの「終了」で閉じてください。

```powershell
.\windows\scripts\Build.ps1 -Test
# 実際のデスクトップへ短時間表示するテストも行う場合
.\windows\scripts\Build.ps1 -DesktopTest
```

コマンドを直接使う場合:

```powershell
Set-Location windows
dotnet publish src/DynamicPhotoWall/DynamicPhotoWall.csproj -c Release -r win-x64 --self-contained true -o ../release/windows/win-x64 -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -p:DebugType=embedded -p:PublishTrimmed=false
dotnet build tests/DynamicPhotoWall.Tests/DynamicPhotoWall.Tests.csproj -c Release
dotnet tests/DynamicPhotoWall.Tests/bin/Release/net10.0-windows10.0.19041.0/DynamicPhotoWall.Tests.dll ../artifacts/windows/smoke-data
```

`--probe --monitor \\.\DISPLAY2 --output <json-path>` は指定画面に4秒間だけ検証ウィンドウを表示し、親・スタイル・座標・破棄結果を記録します。monitor省略時は列挙順の最初の画面です。

実写テスト（上記と同じく `windows` ディレクトリから実行。全画像をデコードし、最も横長の画面へGallery・縦パン・Zoomを短時間表示）:

```powershell
dotnet tests/DynamicPhotoWall.Tests/bin/Release/net10.0-windows10.0.19041.0/DynamicPhotoWall.Tests.dll ../artifacts/actual-photos --scan-only --actual=../photos
```

テストはアプリの通常設定を使わず、指定出力フォルダー配下に専用プロファイルを作ります。実写の確認用PNGはローカルの `artifacts/actual-photos` に保存され、Gitから除外されています。ユーザー写真自体もGitから除外しています。

## 制約

- WorkerW / Progmanは非公開Shell階層です。未知のWindows構成では安全に停止します。全Windows 11ビルドでの互換性は保証できません。
- Explorer再起動・画面変更・スリープ復帰には通知と15秒間隔のHWND確認で復旧します。指定画面が消えても対象外の画面には表示しません。同じモニターでも接続ポート変更でIDが変わる場合は選び直してください。
- 前景の単一ウィンドウがグループ内の全対象画面の作業領域を覆う場合に、そのグループを一時停止します。複数ウィンドウの合計による完全遮蔽、仮想デスクトップの全状態は判定しません。
- JPEGの撮影日時を取得します。WebPは寸法・EXIF向きを取得しますが撮影日時の読み取りには未対応です。HEICは環境のコーデックに依存します。
- 極端な巨大画像は安全のためスキップし、1画像のデコードを約1600万画素に制限します。縦に極端に長い写真のパンでは表示が多少柔らかくなる場合があります。
- 本体は署名なし・インストーラーなしで、単一EXEから起動できます。再配布時は同梱のライセンス類も添付してください。ウルトラワイドでZoomを選ぶと写真の上下を切り取ることがあります。
- Explorerの強制再起動、ケーブルの実際の抜き差し、混在DPI変更、長時間の連続運転は手動受け入れ確認が残っています。
