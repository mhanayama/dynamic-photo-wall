# Dynamic Photo Wall — Windows

Windows 11の選択したディスプレイを、写真がゆっくり動くギャラリーにするWPF常駐アプリです。Windowsの壁紙設定を変更せず、Explorerの背面描画階層に接続します。写真と顔検出は端末内で処理し、クラウドへの写真アップロードやテレメトリは行いません。オンラインモードで接続すると、選択した写真と顔データをLAN内の接続ピアへ転送します。

[Windows版のダウンロード](https://github.com/mhanayama/dynamic-photo-wall/releases/tag/windows-v0.1.0) / [2026-10-19の更新内容](docs/RELEASE-NOTES-2026-10-19.md)。ZIPを展開してEXEを起動してください。更新前に旧版をタスクトレイから終了します。配布ZIPには、本体と依存ライブラリのライセンス・ビルド情報も含みます。

## 起動

**`release/windows/win-x64/DynamicPhotoWall.exe`をダブルクリック**すると起動します。Windows x64向けのReleaseビルドで、.NETランタイム・画像処理ライブラリ・アイコンを同梱した単一EXEです。DLLやPowerShellの操作、.NETの別途インストールは不要です。

同じディレクトリの`Dynamic Photo Wall`ショートカットも同じEXEを起動します。ビルド時に自動で作成・更新します。手動で再作成する場合は `windows\scripts\Create-Shortcut.ps1` を実行してください。

リポジトリ直下から `windows\Start-PhotoWall.ps1` を実行しても起動できます。EXEと同じディレクトリの `photos` を初期の写真フォルダーとして検出します。ルートの既存 `photos` を使う場合は「写真」設定から選択してください。保存済みの写真設定は維持します。

EXEとドキュメント・ライセンス類は `release/windows/win-x64/` に保存します。EXEを別のフォルダーへ移しても起動できます。写真はEXEに含めず、「写真」設定で選択します。設定・キャッシュは引き続きユーザーのLocalAppDataへ保存します。初回起動時には、同梱したマネージド／ネイティブのライブラリを.NETがユーザーの一時領域へ展開します。起動中のEXE差し替えで、後から開くトレイメニューの依存読み込みが失敗する問題を防ぐためです。更新前には引き続き旧版を終了してください。

1. **使用ディスプレイ**で表示対象を1台以上選びます。つなげたい画面がある場合は、**画面グルーピング**で同じグループを選びます。
2. **写真**に写真フォルダーを追加します。複数フォルダーと再帰検索に対応しています。
3. **保存して表示開始**を押します。設定画面は閉じても構いません。
4. タスクトレイから開始・一時停止・次の構成・停止・設定・終了を操作できます。

**使用ディスプレイ → タスクバーを隠す画面**で、タスクバーの表示を画面ごとに指定できます。たとえば連結する2画面の片方だけを隠す設定も可能です。停止・終了、スリープ、対象画面が最大化アプリで覆われたときには、その画面のタスクバーを戻します。対象外の画面のタスクバーは変更しません。アプリが異常終了した場合も独立した復元用プロセスがタスクバーを戻します。「一般」では起動時の動作と再生操作を扱います。

## 複数ディスプレイ

**使用ディスプレイ**で表示対象を選び、**画面グルーピング**でつなぎたい画面に同じグループを選びます。**「独立して表示」の画面は、それぞれ単独で再生**します。たとえば画面1・2を「グループ1」、画面3を「独立して表示」にすると、1・2をまたぐキャンバスと画面3の単独再生を同時に使えます。「＋ グループを追加」で複数のグループも作れます。

初期設定では写真・動き・ガラス風背景をグループ全体へスパンします。表示モードごとの「ディスプレイごとに表示」をONにすると、そのモードだけ各画面の寸法で別々の写真・配置・背景を作ります。グループごとにモード抽選と時計を持ち、ほかのグループへ写真が流れ込むことはありません。写真フォルダーや表示モードの設定は全グループで共通、開始・一時停止・次の構成・停止の操作は全グループへ適用します。

- 初期配置はWindowsの物理ピクセル座標です。カードはグループごとに色分けし、同じグループ内の端・中央へドラッグでスナップします。「配置を数値で調整」のX・Yで上下のずれやベゼルに相当する隙間を指定できます。変更は「保存して適用」または「保存して表示開始」で反映します。
- 「配置を数値で調整」内の「Windowsの配置に戻す」でOSの配置に合わせられます。OSの配置自体は変更しません。画面を新たに接続したときは「ディスプレイを再検出」で一覧を更新して選択してください。
- グルーピング画面の「テストパターン → 表示」を押すと、保存せずに現在編集中の画面選択・配置で位置と倍率を確認できます。写真フォルダーは不要です。ボタンが「表示停止」に変わり、もう一度押すと停止します。もともと写真を再生していた場合は、保存済み設定の写真再生へ戻り、一時停止状態も保持します。テストパターンの表示状態は保存しません。
- グループ一覧には作成済みのグループ数・画面数・所属画面を表示します。未割り当てのグループも「0画面」として表示し、設定を保存すると次回も一覧に残ります。各グループの「削除」でグループを消せます。所属画面は選択・配置・タスクバー設定を維持して「独立して表示」に戻り、保存時に反映します。すべてのグループを削除することもできます。
- 画面を外しても、そのグループの保存済み領域を空けたまま再生を続けます。再接続・解像度変更では該当グループの構成を作り直します。そのグループの全画面が外れた場合は再接続を待ち、ほかのグループは継続します。
- グループ内の全画面を同じ前景ウィンドウが覆う場合は、そのグループの時計を一時停止します。ほかのグループは再生を続けます。タスクバーは画面ごとに復元します。
- 以前の複数画面設定は「グループ1」として連結を維持し、以前のタスクバー設定も引き継ぎます。画面ごとの指定を保存すると個別の設定になります。

キャンバスの幅・高さの上限は32768px。物理サイズが異なる画面の実寸補正、画面の回転設定は今後の対応です。別PCとの同期は試験用のオンラインモードに実装していますが、Mac↔Windowsの実機確認は残っています。OSの表示倍率によらず各画面の物理ピクセルに合わせて切り出しますが、混在DPIの実機確認も残っています。

初回は自動で表示を始めません。保存後は、起動時の再生とWindowsログオン時の自動起動を設定できます。自動起動は現在ユーザーのRunレジストリに実行ファイルを登録します。移動後は設定し直してください。

## モード別の表示範囲と顔の境界回避

「表示モード」の各モード右側に **ディスプレイごとに表示** があります。初期値はすべてOFF（グループ全体へスパン）。たとえばGalleryだけON、Scrolling GalleryはOFFにすると、Galleryは各画面で別々に表示し、Scrolling Galleryはグループ全体を横切ります。設定はモードごとに保存します。

画面ごとの表示でも、グループのモード抽選・フェード・一時停止・Nextは共通です。各画面は自身の物理解像度で写真を選び、パン速度を計算します。移動時間の短い画面は最後の状態で待ち、最も長い画面に合わせて次の構成へ移ります。写真が十分ある場合は画面間の同時重複を避け、不足時は別画面での再使用を許容します。

**小さい写真は動く3モードで自動ミラー**: 横パン・縦パン・拡大では、写真の画素数がグループ長辺の半分未満なら、同じ写真を各画面へ表示します。横長（正方形を含む）グループは向き補正後の写真の横画素数、縦長は縦画素数で比較します。たとえば幅8000pxのグループでは写真の横幅4000px未満が対象で、ちょうど半分はスパンを保ちます。全接続画面で既存のモード適性を満たす場合に限り、各画面でも許容拡大率を超えるパン写真はそのモードの候補から外します。設定やグループ分けは変更しません。手動で「ディスプレイごとに表示」をONにした場合は別々の写真を選びます。

顔の境界対策には、同じページの **スパン時に顔が画面の境目に重ならないよう配置** を使います（初期値ON）。グループを分割せず、検出した顔の矩形と各画面の領域を使って配置を調整します。

- **Gallery**: グループの短辺いっぱいのサイズを保ち、全検出顔の外接矩形が1画面内へ収まる位置を選びます。交換時は隣の写真を移動・退場させ、列全体は縮小しません。移動中の顔の境界通過は許容します。
- **Vertical Pan**: まず写真の横位置を調整します。顔以外の部分は壁の外周で切り取られる場合があります。顔の大きさや複数の顔の広がりで収まらなければ縮小します。画面が上下に並ぶ構成では、内部の横境界を顔が通過しない範囲までパンを短縮します。顔位置で停止する設定がONなら、安全な画面内で顔が見える終点を選びます。
- **Horizontal Pan・Zoom**: 顔の外接矩形が実ディスプレイ1枚に収まる画像サイズ・位置へ調整します。Zoomは全区間、Panは停止位置で顔全体を収めます。Panの移動中の境界通過は許容します。Scrolling Galleryの移動は従来どおりです。

顔を検出できない写真は従来の動きを使います。境界回避の設定はGalleryの配置に適用し、Pan／Zoomの顔サイズ保護は常に行います。未接続画面は安全な配置先に含めず、保存済みキャンバスの領域は維持します。

Galleryは固定した短辺サイズで顔を収められない写真を配置から外します。写真交換では新写真を優先し、必要なら隣の写真を退場させます。通常の写真は全体を表示し、グループより長い写真だけ長辺側の外周を切り取ります。顔保護を使う場合は顔全体が収まる位置を選びます。

## 見せ方

- **Gallery**: 横長グループでは写真の高さ、縦長グループでは幅をほぼいっぱいに固定します（初期余白は各8px）。最大1〜20枚（初期5枚）の範囲で収まる写真を並べます。写真と間隔が収まる空きには追加し、入らなければ交換して隣の写真を移動・退場させます。グループ全体で5〜10秒ごとに1枚を更新し、フェード完了後に次の間隔を数えます。追加・交換直後の写真は、残った写真が一巡するまで交換対象から外します。画面別表示でもグループの交換時計は1つです。
- **Scrolling Gallery**: 従来のGalleryとは別モードです。上下の余白は初期値で各8pxに抑え、写真がゆっくり横に流れ、画面外へ出た写真を新しい写真へ交換します。後続写真を先読みし、同時表示の重複を避けます。速度は「動き」から変更できます。
- **Vertical Pan**: 横幅を画面に合わせ、顔が上側なら写真の下側から上へ、顔が下側なら上側から下へ見せます。顔が見つからない場合は従来どおり下側から上へ進みます。
- 縦パンの幅は初期値で画面幅いっぱいです。Windows標準のローカル顔検出で顔を見つけた場合は、顔全体が収まる画像サイズ・終了位置へ調整します。縮小後の移動距離が20px以下になる写真は、そのパンの候補から外します。顔位置での停止がONなら終了位置で3秒保持します。
- **Horizontal Pan**: 画面より横長の写真を高さに合わせ、顔が左側なら右側から左へ、顔が右側なら左側から右へ見せます。顔が見つからない場合は方向をランダムに選びます。はみ出しがない写真は自動選択しません。
- **Zoom**: 初期値30秒・1.25倍で拡大・縮小します。顔が画面からはみ出す場合は開始・終了の倍率を下げ、倍率の比率を保ったまま全区間で顔を収めます。
- 全画面のZoomでも顔を検出し、顔が画面内に入る縦位置とズーム中心を選びます。「表示モード」の「全画面表示でも顔が見える位置を優先」で切り替えられます。

顔を基準にした方向選択は「動き → 顔の反対側からパンを開始する」で切り替えます（初期値は有効）。複数の顔がある場合は、最も大きな顔の中心を基準にします。縦パンで顔位置に停止する設定も有効なら、同じ顔が見える位置で停止します。方向選択を無効にすると、縦は下から上、横はランダムという従来の動作に戻ります。横スクロールGalleryの方向は変更しません。

パンは物理ピクセルの距離÷速度で時間を決めます。初期値120px/秒、クロスフェード1.2秒、Galleryのグループ共通交換間隔5〜10秒です。旧初期値30〜60秒・10〜30秒は5〜10秒へ移行します。縦パンの横位置は写真全体の中央を基準にし、顔が切れる場合だけ必要な幅を補正します。ミラー表示も各ディスプレイの寸法で中央を計算します。パンの拡大率の初期上限は4倍です。**画面のネイティブ解像度より小さい写真も表示できます。** 粗さが気になる場合は「表示モード」の許容拡大率を下げてください。

縦パンの表示幅の初期値は1.0（画面幅いっぱい）です。顔を画面へ収める縮小処理は維持します。保存済みの幅は保持するため、既存設定の0.96を広げる場合は「表示モード」で1.0に変更して適用してください。

ズームの初期値は30秒で1.00↔1.25倍です。倍率は1.0〜1.5倍で設定でき、開始と終了を滑らかにします。保存済みの時間・倍率は保持するため、旧設定で動きが弱い場合は「動き」で所要時間30秒・最大倍率1.25を入力して適用してください。同期再生中はウォール全体へ共有されます。

顔を考慮したズームも写真の中央配置を基準にし、全顔を実ディスプレイ1枚に収めるために必要な分だけ位置を補正します。顔が端にあるだけで写真全体を移動させず、顔を支点にしたズームと倍率の比率を維持します。

抽選ウェイトは「ギャラリー（静止・スクロール）」80／「パン・ズーム（縦・横・拡大縮小）」20の2系統です。まず系統を抽選し、その中で有効・適性のあるモードを均等に選びます。80%／20%は構成を選ぶ回数の比率で、表示時間の比率ではありません。片方に候補がなければ、表示できる系統から選びます。ウェイト0の系統は除外します。

GalleryとScrolling Galleryが両方有効ならギャラリー系の中で均等に選び、縦Pan・横Pan・Zoomもパン・ズーム系の中で均等に選びます。同じ種類のギャラリーが再当選した場合は結果を捨て、現在の表示を保って5秒後に再抽選します。Gallery→Scrolling Galleryとその逆は許可します。パン・ズームの3連続は同じ系統に別候補がある場合だけ避けます。80%／20%はスキップ分を含む抽選の比率で、実際の切替回数の比率ではありません。「表示モード」で個別に有効・無効を選べます。旧初期値45／35／20は80／20へ移行し、独自に変更した旧ウェイトはPanとZoomを合算します。写真の選択済みフラグは直近履歴とは別に持ち、候補を一巡するまで再使用を避けます。1つのGalleryで同じファイルを重複表示しません。

背景は表示中の写真・切り取り位置に追従するガラス風の色合いです。パン、横スクロール、Galleryの個別更新に合わせて変化します。全5モードで余白を写真の色で埋めてから端の色を保ってぼかし、暗幕を約18%に弱め、装飾グラデーションを除去して画面の端まで色を広げます。「見た目」の「表示中の写真に追従するガラス風の背景」で単色背景へ切り替えられます。写真の4pxのフチぼかしは削除しました。写真の表示サイズをフチ処理のために縮めません。

背景の色が沈みすぎないように、ぼかし後の彩度と明るさを補います。写真由来の色相と階調を保ち、白黒の写真は無彩色のままにします。同期表示でも、写真提供元や進行役のOSにかかわらずWindowsの表示側で同じ補正を一度だけ行います。

Gallery交換時の背景色は、保持した画像の不透明度を経過時間に応じて補間し、急な色変化を抑えます。静止した構図では背景の再生成を止め、写真交換・再配置・Pan／Zoom・スクロール中に更新します。同期表示の背景画像もシーンの間は固定し、不透明度だけを補間します。[描画負荷の改善と検証範囲](docs/RENDERING-PERFORMANCE.md)を参照してください。

同期再生中のモード切り替え・ピア切断・再接続・キャッシュ再生への移行では、ローカル出力が同じなら既存ウィンドウを維持します。次の写真と背景を準備して旧表示の上へ重ね、切り替え完了まで旧表示を残します。

JPEG / PNG / WebP対応。EXIFの8方向の回転・反転を適用します。HEIC / HEIFにはWindowsの対応WICコーデックが必要です。コピー済みの同内容ファイルは別写真として扱います。

## 設定とログ

通常は `%LOCALAPPDATA%\DynamicPhotoWall` に保存します。

- `settings.json`: 設定。テンポラリファイルから置換して保存します。
- `metadata.json`: パス・サイズ・更新日時をキーにした画像情報キャッシュ。
- `faces.json`: ローカル顔検出で取得した顔位置のキャッシュ。
- `app.log`: エラーと復旧記録。約2MBで1世代ローテーションします。パスなどローカル情報を含みます。

設定が壊れている場合はコピーを保存して初期値で起動します。`--data-dir <directory>` で保存場所を変更できます。`--tray` は設定画面を開かず起動します（表示対象が未設定の初回を除く）。フォルダー変更は監視し、通知漏れに備えて5分ごとにキャッシュを使って照合します。

画像デコードはUIスレッド外で行い、画面に合わせたサイズを選びます。LRUキャッシュ予算は初期値256MiBで、全グループで共有します。この予算はキャッシュだけの値で、表示中・プリロード中・WPF/GPUのメモリは別に使用します。デコードは1件ずつ実行し、グループごとに次の構成を1つだけプリロードします。Scrolling Galleryでは次に流入する写真も先読みします。30fps制限は撤廃し、WPFの描画スレッドとDWMの画面合成にペーシングを任せています。パンはRenderTransformで動かすため毎フレームのレイアウト計算が不要です。アプリからDXGIのPresentを直接制御する方式ではなく、厳密な提示フレーム数はWPF・DWM・GPUドライバーに依存します。

## ビルドとテスト

Windows 11 x64、.NET 10 SDKが必要です。ソリューションは `windows/DynamicPhotoWall.sln` です。初回の復元にはNuGet接続が必要です。プロジェクト内の `.tools\dotnet` があればビルドスクリプトが優先します。

リポジトリ直下から実行します。配布物は `release/windows/win-x64/`、検証結果は `artifacts/windows/smoke-data/` に出力します。ルートへEXE・ショートカットをコピーしません。[生成物の共通規則](../docs/GENERATED-FILES.md)に従ってください。再ビルドする前に、起動中のアプリをタスクトレイの「終了」で閉じてください。

```powershell
.\windows\scripts\Build.ps1 -Test
# ZIP・SHA256SUMS.txtも作成する場合
.\windows\scripts\Package.ps1 -Test
# GUI操作の明示的な実行依頼がある場合だけ
.\windows\scripts\Build.ps1 -DesktopTest
```

`-Test`には、顔を考慮したズームの構図・顔保護・画面被覆を調べるGUIなしの`ParityVerifier --zoom-framing`も含みます。`Package.ps1`は配布ファイルを明示的に選び、ローカル写真・設定・絶対パス付きショートカットをZIPへ入れません。ZIP内のEXEと配布EXEのSHA-256一致を確認し、EXEとZIPのチェックサムを生成します。ビルド元コミットと依存バージョンは`BUILD-INFO.txt`へ記録します。パッケージ作業は`artifacts/windows/package/`を使います。

パッケージ時は`Verify-PublishedRuntime.ps1`も実行します。隔離コピーのEXEを起動・待機させ、そのコピーを差し替えた後で`Accessibility`の読み込みとWPF popup bridgeのJITを確認します。`--check-runtime --output <json-path>`はこのGUIなしの診断用で、通常のアプリ・トレイ・写真再生は開始しません。ログと展開先は`artifacts/windows/runtime-check/`です。

## 制約

ネットワークの写真ソースは接続中のものを既定で表示します。「未接続の写真ソースも表示」で保存済みの選択を確認できます。接続済みピアを選び「選択したピアの接続を解除」を押すと、このPCとの接続を切り、オンラインモードを終了するかこのPCから手動で接続し直すまで自動再接続を止めます。画面配置・写真ソースの選択・キャッシュは保持します。

ネットワーク機能の開発版を追加しました。「ネットワーク」でオンラインを有効にし、接続候補から接続します。全ピアの画面をグループ／単独表示へ配置し、写真ソース適用後に原寸と顔データを暗号化転送します。進行役交代・共通時計による予約表示・60秒後の単体動作も含みます。責任分割・試験とMac側の未検証事項は[実装記録](../docs/NETWORK-CORE.md)を参照してください。

- WorkerW / Progmanは非公開Shell階層です。未知のWindows構成では安全に停止します。全Windows 11ビルドでの互換性は保証できません。
- Explorer再起動・画面変更・スリープ復帰には通知と15秒間隔のHWND確認で復旧します。指定画面が消えても対象外の画面には表示しません。同じモニターでも接続ポート変更でIDが変わる場合は選び直してください。
- 前景の単一ウィンドウがグループ内の全対象画面の作業領域を覆う場合に、そのグループを一時停止します。複数ウィンドウの合計による完全遮蔽、仮想デスクトップの全状態は判定しません。
- JPEGの撮影日時を取得します。WebPは寸法・EXIF向きを取得しますが撮影日時の読み取りには未対応です。HEICは環境のコーデックに依存します。
- 極端な巨大画像は安全のためスキップし、1画像のデコードを約1600万画素に制限します。縦に極端に長い写真のパンでは表示が多少柔らかくなる場合があります。
- 本体は署名なし・インストーラーなしで、単一EXEから起動できます。再配布時は同梱のライセンス類も添付してください。ウルトラワイドでZoomを選ぶと写真の上下を切り取ることがあります。
- Explorerの強制再起動、ケーブルの実際の抜き差し、混在DPI変更、長時間の連続運転は手動受け入れ確認が残っています。
