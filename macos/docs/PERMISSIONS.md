# Macの起動時アクセス権限

1.1.0 build 11では、通常起動・ログイン起動時に写真ライブラリ、通知、ローカルネットワーク、登録済みフォルダーを確認する。不足があれば設定ウィンドウの「アクセス権限の確認」を開く。「不足している権限を取得」から写真 → 通知 → フォルダー → LANの順に進む。macOSの確認は項目ごとに必要で、アプリが代わりに許可することはできない。build 8〜10にあったKeychainの項目とOSへのアクセス要求は廃止した。

写真はPhotoKitのread/write認可状態を読み、初回だけ要求する。制限付き許可も利用可能として扱い、拒否済み・管理制限の場合はシステム設定へ案内する。写真アプリのアルバムと原写真へのアクセスを指し、独立した「フォトストリーム」の権限ではない。通知も初回だけ要求し、拒否しても写真表示・LAN同期を止めない。

通信鍵と信頼情報は、ユーザーが選択したKeychain非使用方式で保存する。起動・権限確認・オンライン化・信頼情報保存・旧版からの切替のいずれでもKeychainへアクセスしない。ファイルはアプリ専用領域の所有者のみ読書き可とし、TLSと写真・設定の暗号化は維持する。鍵ファイル自体は独立したパスワード等で暗号化せず、同一ユーザー権限の別プロセスに対する保護はKeychainより弱い。[保存仕様と旧データの扱い](LOCAL-NETWORK-STORAGE.md)を参照。

登録済みフォルダーはbookmarkを再確認し、読めないものだけ選択パネルで同じ場所を選び直す。権限不足とドライブ未接続を確実に区別できないため、外付けドライブの接続確認も案内する。更新したbookmarkは同じフォルダーIDで保存し、表示モード・画面配置・アルバム等の未保存ドラフトを一緒に保存しない。途中取消や別フォルダーの選択で登録を削除しない。

ローカルネットワークには許可状態を返す一般APIがない。初回・実行ファイル更新後は説明画面から`_photowall._tcp`のBonjour探索を行う。保存するのは署名のCodeDirectory hashと「この実行ファイルで取得フローを実施した」という記録だけであり、許可フラグとして扱わない。同じ実行ファイルの次回起動でも実際の探索で確認し直す。`PolicyDenied`は初回のOS確認中にも発生するため即座に拒否と断定せず、最大30秒待つ。確認不能なら利用可能と表示せず、システム設定と再試行を案内する。探索は接続・写真公開・壁への参加を開始しない。完了・中止時に探索と待機タスクを破棄する。実際のピア探索は既存のUDP multicastのまま。

「あとで」で閉じても、利用可能なローカル写真やフォルダーでの処理は継続する。写真の許可後は保存済みアルバムを再検索する。LANを確認できるまでは記憶したオンラインモードの自動復帰を待つ。旧通信データがあれば、新しい通信設定の作成を明示的に選ぶまではオンライン化を保留する。システム設定から戻った時も再確認する。設定上部の「アクセス権限を確認…」から後で開き直せる。

## アプリ更新と署名

現在のローカル配布候補はアドホック署名であり、アプリを置き換えた後の権限の継続を保証できない。権限の自動移植・OS側の認可データ書換えは行わない。配布時に同じApple発行の署名identityで署名し続けることは別途必要になる。

根拠はAppleの[TN3179: Understanding local network privacy](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)（確認APIの制約、Network.frameworkのPolicyDenied、macOSでの署名identity）と[TN2206: macOS Code Signing In Depth](https://developer.apple.com/library/archive/technotes/tn2206/_index.html)（更新を同一アプリと認識するdesignated requirement）。

## 検証

`StartupPermissionsTests`は注入した認可クライアントで確認と取得を分離し、要求順序・中止・遅れて返る結果・拒否・フォルダー再許可の独立保存・写真だけの復旧を検証する。`NetworkAvailabilityTests`と`FileSecretsTests`は秘密ストアの初期化・失敗時の停止・所有者のみのファイル権限・旧通信データの保持を検証する。通常の設定やOSの認可状態、写真ライブラリには触れず、Keychain項目を操作する試験も廃止した。GUI操作・実OS確認ダイアログの自動テストは行わない。APPを実際に置き換えた後のOS確認、システム設定からの復帰、実LANなし／拒否、実フォルダー再許可は手動受け入れの残件。
