# Dynamic Photo Wall — macOS

Apple Silicon搭載Mac、macOS 27.0以降、Xcode 27.0向けです。SwiftUI＋AppKitで写真を対象ディスプレイの背面へ表示します。App Sandboxと、ユーザーが選択したフォルダーへの読取り権限を使用します。

**2026-10-17の実装:** Windows先行機能D01〜D09を反映しました。複数画面・独立グループ、グループ追加／削除、即時テスト表示、顔の反対側からのパン、モード別の画面単位表示、スパン時の顔境界回避、小さい縦写真の自動ミラー、顔キャッシュによるGalleryの余白改善に対応します。[仕様](WINDOWS_DELTA_HANDOVER.md) / [検証記録](docs/TEST-RESULTS-2026-10-17.md)。実ケーブル抜差し・混在倍率・長時間運転などの実機受け入れは継続中です。

**生成物の共通規則:** 配布物は `release/macos/arm64/`、作業・検証ファイルは `artifacts/macos/`。プロジェクトルート直下へAPP・ZIP・DMG・ログ・一時ファイルを置きません。[共通規則](../docs/GENERATED-FILES.md)と[AGENTS.md](../AGENTS.md)に従ってください。

## 起動と設定

```sh
open macos/DynamicPhotoWall.xcodeproj
```

`DynamicPhotoWall` スキームでRunし、写真フォルダーまたは写真アプリのアルバムと対象画面を選んで「保存して適用」を押すと再生を開始します。フォルダーはJPEG／PNG／WebP／HEIC／HEIFを扱います。

起動時に不足している権限があれば「アクセス権限の確認」を開きます。「不足している権限を取得」で写真・通知・登録済みフォルダー・LANを順に確認してください。OSの確認は項目ごとに必要です。「あとで」で使える機能を続け、設定上部から開き直すこともできます。build 11からKeychainは使いません。[取得フロー・アプリ置換時の制約](docs/PERMISSIONS.md)を参照してください。

「写真」ページの「アルバムを追加」から、システム写真ライブラリの通常アルバム・スマートアルバム（お気に入りなど）を複数選べます。初回はmacOSの写真アクセスを許可してください。フォルダーとの併用、アルバムだけでの再生が可能です。同じ写真が複数のアルバムにある場合は重複を除外し、動画・非表示の写真は除きます。Live Photosは静止画として表示します。編集済みの写真を使用し、iCloudにだけある写真は表示・先読み時にPhotoKitでダウンロードします。

アルバムの追加・削除も「保存して適用」までドラフトです。選択は再起動後に復元し、写真の追加・削除・編集は変更通知と5分ごとの照合で反映します。削除されたアルバムやアクセス拒否は警告を表示し、登録自体は保持します。許可し直した後は「再検索」で再試行できます。PhotoKitが扱うのはシステム写真ライブラリで、任意の `.photoslibrary` ファイルの指定には対応していません。

アルバムを追加すると自動で写真をスキャンし、選択したアルバム全体の枚数を表示します。この時点では現在の再生を変更しません。「保存して適用」を押すと、選択時のスキャン結果を使って再生を開始します。スキャン中に押した場合も、完了後に自動で開始します。停止中・一時停止中からも適用で再生を開始するため、別途「保存して表示開始」を押す必要はありません。

アルバム選択・保存・取消・再起動・アクセス失敗からの再試行はfakeの写真一覧で自動検証します。実際の写真アクセス許可、変更通知、iCloudからの取得は実機受け入れの残件です。

フォルダーは行のゴミ箱、または複数選択して「選択を削除」で解除できます。画面・フォルダー・各設定は「保存して適用」までドラフトです。「変更を取り消す」または設定ウィンドウを閉じると、未保存の変更を破棄します。メニューからの開始は適用済みの設定を使います。

設定を閉じても再生とメニューは継続します。メニューバーから開始／停止／一時停止／次／設定再表示／終了を操作できます。通常起動は設定画面を表示し、設定済みのログイン起動はメニューへ常駐します。ログイン起動と、アプリ起動時に再生する設定は独立しています。ログイン項目が承認待ちの場合は、システム設定で許可します。

Dock／メニューバーの表示はmacOS側の設定に従います。これはWindowsの対象画面限定タスクバー非表示との、ユーザー合意済みのOS差分です。

## 複数画面・グループ・一時テスト表示

「使用ディスプレイ」で表示する画面を複数選び、「画面グルーピング」で同じグループへ割り当てます。「独立して表示」は画面ごとに別再生です。同じグループはモード・時計・フェード・写真履歴を共有します。配置は物理pxでドラッグして端・中央へスナップでき、X/Yの数値入力とOS配置へのリセットは折りたたみ内にあります。OSの画面配置は変更しません。

空グループも保存します。削除したグループの画面は、未選択画面も含めて独立表示へ戻し、選択と座標を保持します。追加／削除／所属／配置はすべてドラフトです。未接続画面の領域は詰めずに保持し、全画面が切れたグループだけ待機します。

グルーピングの「テストパターン → 表示」は、未保存の配置を写真・保存なしで即表示します。「表示停止」で適用済みの写真再生へ戻り、元の手動一時停止も保ちます。表示前が停止中なら停止へ戻ります。設定画面を閉じる／取り消す／保存する操作では一時表示を解除せず、開始時の配置を維持します。通常開始・全体停止・アプリ終了は一時表示を解除し、再起動で復元しません。

「表示モード」はチェックボックスで再生候補を選び、その下の「表示方法」で「グループ全体につなぐ」（初期値）または「ディスプレイごとに表示」を選びます。モードをOFFにすると表示方法の操作は無効になり、選択値は保持します。画面ごとの表示では画面IDごとの写真・構成・背景を使います。写真が少なければ別画面への再使用を許容します。短いパンは終点で待ち、グループ内で最長の構成に合わせて切り替えます。

スパンのGalleryと縦Panは、全検出顔の外接矩形が接続画面の内側へ入るよう配置します。Galleryの交換は既存スロットを滑らかに移動し、交換写真だけをフェードします。移動中の顔の境界通過は許容します。

横Pan・縦Pan・Zoomでは、グループの長辺方向で写真の画素数が半分未満なら、同じ写真を各画面へ自動ミラーします。横長（正方形を含む）は向き補正後の横画素数、縦長は縦画素数を比較し、ちょうど半分はスパンを保ちます。全接続画面で既存のモード適性を満たす必要があり、各画面でも許容拡大率を超えるパン写真はそのモードから除外します。設定やグループ分けは変えません。全5モードの背景は余白と端まで写真の色を伸ばし、暗幕を18%に弱めます。背景の色差と明るさもRGBの余裕の範囲で補い、無彩色とアルファを保ちます。同期用PNGは補正せず送り、受信側で一度だけ補正します。この2026-10-18の改定はMacの単体テストとReleaseビルドで確認しています。実画面での見え方は手動確認の対象です。

Galleryは横長グループでは写真の高さ、縦長グループでは幅をほぼいっぱいに固定します。写真と間隔が収まる空きには追加し、入らなければ交換して隣の写真を移動・退場させます。写真列は縮めません。グループより長い単写真は長辺側の外周を切り取り、顔保護を使う場合は全顔が収まる位置を選びます。更新時計は画面別表示でもグループに1つだけ置き、初期値5〜10秒で1枚を更新します。次の待ち時間は前のフェード完了後から数えます。旧初期値30〜60秒・10〜30秒は5〜10秒へ移行します。追加・交換した写真は残りの写真が一巡するまで交換対象から外し、選択済みフラグでも同じ候補の偏った再使用を避けます。今回追加した待機時間・一巡フラグ・再当選スキップ等の変更は、Macではビルド・実行未確認です。

Galleryの最大枚数は1〜20枚で設定できます（初期値5枚）。固定サイズで収まる枚数をこの上限内で並べます。ネットワーク共有設定も同じ範囲です。

抽選ウェイトは「ギャラリー（静止・スクロール）」80／「パン・ズーム（縦・横・拡大縮小）」20の2系統です。系統を先に抽選し、その中の有効・適性のあるモードを均等に選びます。同種のギャラリーが再当選したら現在の表示を保って5秒後に再抽選します。GalleryとScrolling Galleryの相互切替は許可します。この割合はスキップ分を含む抽選の比率で、実際の切替回数・表示時間の比率ではありません。旧初期値45／35／20は80／20へ移行し、旧カスタム設定のPanとZoomは合算します。単画面・グループ・ネットワークの進行役は同じ方針です。縦パンは各出力の写真全体を中央に置き、顔のための移動を必要最小限にします。今回追加した待機時間・一巡フラグ・再当選スキップ等の変更は、Macではビルド・実行未確認です。

「動き」の顔方向設定は初期値ONです。最大の顔の反対側から縦横Panを開始します。顔停止・Zoomの顔優先設定とは独立し、顔なし／方向OFFでは従来の方向を使います。

縦Pan・横Pan・Zoomは、全検出顔の外接矩形が実ディスプレイ1枚に収まるよう画像サイズ・位置を調整します。Zoomは開始と終了の倍率を同じ割合で下げ、動きの比率を保ちます。Panは画像を縮め、停止位置で顔を収めます。縮小後に20pxを超える移動が残らない写真は、そのPanの候補から外します。顔方向・停止設定と独立した安全処理です。この2026-10-19の変更はMacの単体テストで確認し、実画面の確認は残します。

縦Panの表示幅の初期値は1.0（画面幅いっぱい）です。顔を画面へ収める縮小処理と保存済みの幅は保持します。既存設定の0.96を広げる場合は「表示モード」で1.0に変更して適用してください。

Zoomの初期値は30秒・1.25倍で、倍率の範囲は1.0〜1.5倍です。動きがはっきり分かる幅を基準とし、従来の滑らかな開始・終了と顔優先を保ちます。保存済み設定は変更せず、既存のウォールは「動き」で30秒・1.25倍を入力して適用します。初期値・共有設定・既存値の保持・拡大縮小の両方向はMacの単体テストで確認しています。

build 10では、背景の色を再生時刻に基づく0.8秒基準の平滑化へ変更し、更新ごとの小画像を125msで補間します。途中で色が変わっても、その時点で見えている混色からつなぎます。一時停止中は色と補間も止まり、定常色の彩度・明るさを保ちます。同期表示は準備済みサンプル間を連続補間します。GUI操作を伴わない検証と実機残件は[2026-10-19の記録](docs/TEST-RESULTS-2026-10-19.md)を参照してください。

## 機能と保存

5モード、重み・履歴・逐次選択、次構成の先読み、Galleryのグループ共通交換、連続スクロール、顔を考慮したPan／Zoom、表示中の切抜きに追従する小画像背景を実装しています。画像準備や再走査中も旧ビットマップを保持します。写真変更はイベント監視で約1秒後に反映し、5分ごとの照合も行います。対象画面が前面アプリに覆われると休止し、ユーザーpause・スリープと独立して復帰します。

本番データはsandbox内のApplication Supportの `DynamicPhotoWall/` に保存します。

- `settings.json`: 画面・設定・フォルダーブックマーク・写真アルバムIDの原子的保存。直前の保存は `.previous`、破損原本は `.invalid-UUID` へ退避。
- `metadata.json`／`faces.json`: ファイル更新情報に基づくキャッシュ。顔キャッシュは最大10,000件。
- `app.log`／`app.log.1`: 約2MBで1世代のログ。写真のパスやエラーを含むローカル診断情報。
- `network/local-v2/`: 通信設定と暗号化キャッシュ。鍵と信頼情報は`credentials/`に所有者だけが読書きできるファイルとして保存し、Keychainへのアクセスは行いません。鍵ファイル自体は平文のため、同じユーザー権限の別プロセスに対する保護はKeychainより弱くなります。旧版の通信データは残し、必要ならネットワーク設定で「新しい通信設定を作成」を選び、他の端末と接続し直します。[保護の範囲と切替手順](docs/LOCAL-NETWORK-STORAGE.md)を参照してください。

従来のUserDefaults・単一／複数ブックマークは、初回の保存時に新形式へ移行します。解決不能なフォルダー登録は、明示的に削除するまで保持します。

## CLIビルドと隔離テスト

リポジトリ直下で実行します。テスト実行にはXcodeと.NET 10 SDKが必要です。

```sh
bash macos/scripts/verify.sh
```

既定ではGUI操作を行わず、単体テスト、Windows Coreの共通fixture照合、OS非依存ネットワーク試験、arm64 Releaseコンパイルを実行します。`--unit-only`も同じ動作です。実操作付きUIテストは、ユーザーから明示的な指示がある場合に限り`--ui`を指定します。ログ・DerivedDataは `artifacts/macos/verification/`（Git対象外）です。

テスト用アプリIDは `asia.dix.mhanayama.DynamicPhotoWall.Regression`。通常アプリと別のsandbox／UserDefaultsを使います。UIテストにはfake画面・写真一覧・ログイン登録・デスクトップhostを渡すため、ユーザーの写真や表示中の壁、ログイン項目を変更しません。実画像テストは公開fixtureと一時ディレクトリを使います。

アプリを起動せずコンパイルだけ確認する場合:

```sh
xcodebuild build-for-testing \
  -project macos/DynamicPhotoWall.xcodeproj -scheme DynamicPhotoWall \
  -destination 'platform=macOS,arch=arm64' \
  -derivedDataPath artifacts/macos/compile/DerivedData CODE_SIGNING_ALLOWED=NO
```

## Release候補のパッケージ化

```sh
bash macos/scripts/package.sh
```

`release/macos/arm64/` にアドホック署名付きの`DynamicPhotoWall.app`、ZIP／DMG、SHA256SUMSを生成します。APPはそのまま直接起動できます。すべて同じReleaseのAPPから作り、署名・CPU構成・ZIP／DMGの検査後に既存のローカル配布物を置き換えます。旧配布物は`artifacts/macos/package/previous-release.*/`へ退避します。arm64専用archive・DerivedData・ログも `artifacts/macos/package/` へ分け、DMG stagingはOS標準の一時ディレクトリを使います。Developer ID署名・公証・GitHubへの公開は含みません。XcodeのProduct → Archiveも利用できますが、リポジトリ内の生成物は共通規則に従って配置してください。

現在のローカル候補は1.1.0 build 11。リモート`39bbdb9`のGallery・顔安全処理・抽選・Zoom調整と背景の平滑化に加え、ユーザーが選択した[Keychainを使わない保存方式](docs/LOCAL-NETWORK-STORAGE.md)へ変更しました。写真・通知・LAN・フォルダーの権限取得と表示面の保持も維持します。[今回の差分と検証](docs/TEST-RESULTS-2026-10-19.md)を参照してください。

DMG用の一時フォルダはプロジェクト外に作成し、終了時に削除します。DMG内の `/Applications` リンクをエディタがたどって大量のファイルを検索することを防ぎます。VS Codeのワークスペース設定でもビルド生成物をファイル一覧・検索・監視から除外しています。

[macOS v1.1.0（build 4）](https://github.com/mhanayama/dynamic-photo-wall/releases/tag/macos-v1.1.0)は2026-10-18の更新です。変更点と検証状況は[リリースノート](docs/RELEASE-NOTES-v1.1.0.md)を参照してください。v1.0.1以前のReleaseも保持します。[実機受け入れの残件](MACOS_PARITY_TODO.md#release前に残す実機受け入れ)は継続管理します。Spaces、実ログイン、画面抜差し、8時間運転は未検証で、自動テストの合格に含みません。

## ネットワーク機能の追加実装

写真ソースは接続中のものを既定で表示し、「未接続の写真ソースも表示」で保存済みの選択を確認できます。接続済みピアの「接続解除」はこのMacとの接続を切り、オンラインモードを終了するかこのMacから手動で接続し直すまで自動再接続を止めます。画面配置・ソース選択・キャッシュは保持します。この変更と`NetworkDisconnectTests`のMacでのビルド・実行確認は未実施です。

Swiftネイティブの通信・Keychain保存・PhotoKit原写真転送・同期表示を`DynamicPhotoWall/Networking/`へ分割して追加しました。既存の単体表示と、Dock／メニューバーをOS設定に従わせる方針を保持します。2026-10-18にMacのコンパイル修正と隔離検証を実施しました。[結果と実機残件](docs/NETWORK-TEST-RESULTS-2026-10-18.md)を参照してください。公開済みv1.1.0の検証結果に含めないでください。

「ネットワーク」のオンラインモードを有効にすると待受と自動検出を開始します。候補の「接続」から参加し、受信側の確認操作は不要です。「使用ディスプレイ」「画面グルーピング」は全ピアの共通一覧へ切り替わり、共有する写真ソースは選択後に「保存して適用」で確定します。オンライン切替は即時の端末操作で、共有設定のドラフトとは独立します。

`bash macos/scripts/verify.sh --unit-only`で共有fixture・暗号文の復号・期限・切断状態・予約Commit・専用ファイル保存／TLSを検証できます。別プロセスのSwift／.NET間のTLSは`bash macos/scripts/verify-network-interop.sh`、multicast相互検出を含める場合は`--with-discovery`を付けます。出力は`artifacts/macos/network-interop/`です。実際のMac↔Windowsの手動確認項目は[ネットワーク実装記録](../docs/NETWORK-CORE.md#手元のMacでの確認)へまとめました。
